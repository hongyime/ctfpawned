## Scenario

Sesame took over staff tokens after Nought's badge printer became a report
paragraph. He closed the obvious shortcut, added a signature check, and has been
telling everyone that the new tokens are "properly protected" because changing
the role now breaks the signature.

The adoption office uses this target to preview staff-only intake notes. Your
starting token belongs to a volunteer account. The admin notes are visible only
after the page accepts a token with stronger privileges. Sesame included a
twenty-word list of possible signing phrases in the troubleshooting drawer
because he did not want weekend staff to get locked out of tests.

Your review is to find out whether the signature proves control by the server
or whether the key material is weak enough that a browser user can reproduce
it. The target includes helper functions so the exercise is about the security
decision, not about tedious string formatting.

Win condition: produce a modified token that passes the target's signature
check and recover the flag derived from that accepted token.
